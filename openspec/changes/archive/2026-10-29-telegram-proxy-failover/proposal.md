# Proposal: Автоматическая смена серверов прокси для уведомлений в Telegram

## Why

С боевого сервера api.telegram.org напрямую недоступен. Уведомления идут через контейнер Xray, а в его `xray-config.json` вручную вписан **один** VLESS-сервер из VPN-подписки Krepost. Сервер живёт в среднем пару дней. Когда он умирает, уведомления о заказах, правках, остатках и реестре оплат молча пропадают: после 3 повторов через тот же мёртвый прокси сообщение теряется, остаётся только строка в логе. Узнают об этом, когда кто-то не получил заказ, а чинят ручной правкой конфига на сервере.

В подписке около 10 серверов. Система должна сама переключаться на живой сервер, когда сообщение не уходит, сама подтягивать актуальный список серверов из подписки и не терять сообщения, если временно не работает ни один сервер.

## What Changes

- **Свой образ `xray`** вместо `teddysun/xray`: бинарь Xray плюс скрипт-супервизор.
  - Скрипт скачивает подписку по `XRAY_SUBSCRIPTION_URL` из `.env` при старте и раз в 6 часов. Ссылка хранится только на сервере, в git её нет.
  - Из подписки берутся только ссылки `vless://`, остальные пропускаются с записью в лог.
  - Скрипт собирает конфиг Xray: отдельный SOCKS-порт `10801…10800+N` на каждый сервер.
  - Рядом в общий том скрипт пишет манифест серверов.
  - Если список серверов изменился, скрипт перезапускает Xray.
  - Если подписка недоступна, остаются прежние конфиг и манифест.
- **Поиск рабочего сервера при сбое отправки.**
  - Приложение помнит текущий сервер.
  - При сетевой ошибке или таймауте приложение по кругу пробует остальные серверы из манифеста с тем же сообщением и запоминает первый, через который сообщение ушло.
  - Ответ Telegram `4xx` (неверный токен или чат) поиск не запускает.
  - Одновременные сбои ждут один общий поиск.
- **Очередь недоставленных** (`telegram_outbox`).
  - В очередь попадает сообщение, которое не ушло ни через один сервер.
  - Раз в 5 минут очередь досылается по порядку.
  - Сообщения старше 24 часов отбрасываются.
  - У досланного сообщения в тексте появляется строка `⏱ Задержано: создано ЧЧ:ММ`.
- **Поле «Прокси» в Настройках.**
  - Если манифест есть, работает автоматика, а поле игнорируется.
  - Если манифеста нет (dev, другой хостинг), всё работает как сейчас.
  - `TELEGRAM_PROXY_URL` в `docker-compose.yml` по умолчанию становится пустым.
- **Статус в Настройках** (только admin, только чтение):
  - текущий сервер «N из M» и с какого времени он текущий;
  - последнее переключение и его причина;
  - время последнего обновления подписки и число серверов, с предупреждением, если подписка не обновлялась больше суток;
  - размер очереди.
- **BREAKING (деплой).** На сервере один раз:
  - прописать `XRAY_SUBSCRIPTION_URL` в `.env`;
  - пересобрать `docker compose up -d --build`.

  Ручной `xray-config.json` больше не используется.

## Capabilities

### New Capabilities
- `notifications/telegram-delivery`: доставка уведомлений в Telegram через пул серверов прокси из подписки: поиск рабочего сервера при сбое, очередь недоставленных, статус для admin, ручной прокси как запасной режим.

### Modified Capabilities
—. Тексты, чаты, темы и правила отправки уведомлений (`orders/order-edit`, а также не архивированные `reestr-oplat`, `reestr-bulk`, `order-hired-delivery`) не меняются. Меняется только способ доставки.

## Impact

- **Деплой:**
  - новый каталог `xray/`: `Dockerfile`, супервизор, разбор подписки, генерация конфига;
  - `docker-compose.yml`: сервис `xray` собирается из `xray/`, том `./xray-state` (у xray на запись, у calc на чтение), `XRAY_SUBSCRIPTION_URL`, пустой `TELEGRAM_PROXY_URL`;
  - `.env.example`.
- **Backend:**
  - `telegram.js`: чтение манифеста, текущий сервер, поиск, очередь, классификация ошибок;
  - `schema.sql`: таблица `telegram_outbox`;
  - `server.js`: таймер очереди;
  - `router.js`: `GET /api/config/telegram-status` (admin).
- **Frontend v2:** `screen-settings.js`, блок статуса в разделе «Уведомления в Telegram».
- **Не затрагивается:**
  - тексты уведомлений, выбор чата и темы, бот;
  - когда и о чём уведомлять;
  - операции (заказ, заявка, движения остатков) не ждут отправки и не отменяются из-за неё;
  - fallback токена и чата на env;
  - подмена `telegram.transport.post` в тестах;
  - права: раздел Telegram по-прежнему только для admin.

## Out of Scope

- Протоколы подписки, кроме VLESS (vmess, trojan, shadowsocks и т.п.).
- Периодическая фоновая проверка серверов (Xray `observatory`): серверы проверяются только реальной отправкой.
- Ручное переключение сервера и очистка очереди из интерфейса.
- Уведомления о переключении сервера в сам Telegram.
- Несколько подписок или разные провайдеры одновременно.
- Сохранение «текущего сервера» между перезапусками `calc`: после старта поиск начинается с первого сервера.
- Прокси для других исходящих запросов (Mail.ru WebDAV и т.п.).

## Dependencies

- Блокирующих нет.
- Совместимо с `reestr-oplat`, `reestr-bulk` и `order-hired-delivery`: они вызывают `telegram.notifyRegistry` и `send()` без `await`, и это сохраняется. Сообщения из этих change тоже попадают в очередь при полном сбое.
- Тест `registry-notifications.test.js` (сценарий «Telegram недоступен») после изменения кладёт сообщение в очередь. Очистка `telegram_outbox` добавляется в хелпер тестов.
