# Дизайн: выгрузка путевых по месяцам с реестром

## Формирование архива

Существующая сборка документов формы 4-С остаётся источником данных и печатных книг. После группировки и присвоения номеров экспорт сортирует уже созданные документы по дате рейса и номеру документа для стабильного порядка. Для каждой путёвки путь внутри ZIP имеет вид `Месяц ГГГГ/имя файла`, где месяц задан русским названием. ZIP формируется и при единственном документе, чтобы формат оставался единым и включал реестр.

Выбор по одной или нескольким исходным записям сохраняет действующую семантику: если запись входит в групповой документ, экспорт содержит весь этот документ. Пустой выбор документов по-прежнему возвращает ошибку.

## Реестр

Один файл `Реестр путевых.xlsx` размещается в корне архива. На листе «Реестр» есть одна строка на каждый сформированный документ. Колонки: месяц, дата, номер путевого, водитель, транспорт, маршрут/пункт назначения, число рейсов, пробег, норма топлива, фактический расход, выдано топлива, остаток при выезде и остаток при возвращении.

Расход топлива берётся непосредственно из документа: `totalFuelLiters` — норма, `fuelFactLiters` — факт, `fuelIssued` — выдача, `fuelBalanceAtDeparture` и `fuelBalanceAtReturn` — баковые остатки. Реестр не пересчитывает значения и не обращается к другим данным. Пробег суммируется как `distanceKm × 2 × tripCount` по маршрутам документа; число рейсов — сумма `tripCount`. Если маршрут содержит несколько пунктов, они перечисляются в одной ячейке.

После строк каждого месяца добавляется строка итога месяца; в конце — общий итог. Суммируются число путевых, рейсы, пробег, норма, факт и выдача. Остатки в баке остаются значениями строк и не складываются, так как это моментальные балансы. Все литровые значения выводятся с точностью до 0,1 л, согласно источнику; выдача сохраняет целые литры.

## Компоненты и границы

- `backend/waybill-xlsx-4s.js`: добавляет месячные пути и сборку ZIP с дополнительной книгой реестра.
- Новый `backend/waybill-registry-xlsx.js`: формирует OOXML-книгу на существующем серверном XLSX-писателе.
- `backend/router.js`: всегда отвечает ZIP для указанного API-экспорта.
- `frontend/js/shared/waybill.js`: сохраняет расширение `.zip` для этого экспорта.
- Расчёты топлива в `waybill-docs.js` и модель данных не меняются.

Реестр использует сведения, уже присутствующие в сформированном путевом документе, и не добавляет новые персональные идентификаторы.
