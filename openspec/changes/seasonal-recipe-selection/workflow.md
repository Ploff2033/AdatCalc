# Workflow: сезонные копии и доступность рецептов

- Маршрут: small-change — новое ограниченное поведение справочника рецептов и выбора рецепта в v2.
- Этап: verification.
- Цель: копировать сезонные рецептуры и вручную управлять доступностью вариантов при создании новых заказов во второй версии интерфейса.
- Границы и решения: копия сохраняется как независимый рецепт того же завода, с новым ID, прайсовой ценой и составом; сезонное обозначение и имя менеджер задаёт вручную. Клиентские цены не копируются. Копия выключена, новый рецепт с нуля включён; все существующие рецепты после миграции включены. Доступность ведётся отдельно по каждому рецепту, варианты одной марки могут быть доступны одновременно. Новые заказы v2 показывают только включённые рецепты; при исправлении доступны все. Выключенные рецепты остаются в каталоге и истории. `/` и поведение API создания заказов для v1 не меняются; v1 продолжит использовать выключенные для v2 рецепты. Управление — текущая роль manager+.
- Согласование интервью: 2026-11-18, пользователь подтвердил общую модель поведения, включая копирование в пределах завода, статус копии, отдельные клиентские цены, выбор всех вариантов при исправлении и неизменность интерфейса v1.
- Пакет: `proposal.md`, `specs/recipes/catalog-management/spec.md`, `design.md`, `tasks.md`.
- Согласование пакета: пользователь разрешил реализацию 2026-11-18 с уточнением «по визуалу опирайся на текущий UI», пакет реализуется в его границах.
- Реализация: добавлен флаг доступности рецепта, копирование рецепта в v2, локальное переключение доступности, фильтрация новых заказов v2 и полный список при исправлении. `frontend/` не менялся.
- Данные для сезонной приёмки: в локальной базе `calc` для «Джаги» добавлено 15 зимних копий, для «Теберды» — 16; на каждом заводе добавлен материал «Криопласт Альфа» (кг, 53 ₽).
