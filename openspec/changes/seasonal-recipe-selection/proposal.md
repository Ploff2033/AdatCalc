# Proposal

## Why

Для сезонной замены состава одной марки менеджеру сейчас приходится заводить рецептуру заново. При этом старый вариант остаётся доступен в заказе, а его удаление не подходит: рецептура нужна в справочнике и в истории. Копирование и ручное включение вариантов в заказах v2 позволят подготовить сезонную рецептуру заранее и переключать доступность по фактической погоде.

## What Changes

- В справочнике рецептов v2 можно создать копию рецепта того же завода с его составом и прайсовой ценой, вручную изменить название и сохранить как выключенный для новых заказов вариант.
- Для каждого рецепта менеджер v2 включает или выключает доступность при создании новых заказов. Несколько рецептов, в том числе сезонные версии одной марки, могут быть доступны одновременно.
- Все текущие рецепты при внедрении останутся доступными; новая рецептура, созданная с нуля, будет доступна сразу.
- В форме нового заказа v2 доступны только включённые рецепты. В форме исправления можно выбирать все варианты.
- Клиентские цены, составленные для исходного рецепта, не копируются в новый рецепт.
- Интерфейс v1 не меняется: там выключенные рецепты остаются доступными для заказов.

## Capabilities

### New Capabilities

- `recipes/catalog-management`: копирование рецептур и управление доступностью вариантов в интерфейсе v2.

### Modified Capabilities

- Нет.

## Impact

- База данных и API справочника рецептов: признак доступности с включённым значением по умолчанию; старые записи сохраняют доступность.
- `frontend-v2`: экран справочника рецептов, формы нового заказа на ПК и телефоне, форма исправления.
- История заказов, клиентские цены и интерфейс `frontend/` не меняются. Общие API остаются совместимыми со старым интерфейсом; сервер не запрещает v1 отправлять выключенный рецепт.

## Out of Scope

- Автоматическое определение сезона, календарное переключение, отдельное поле сезона или марки.
- Перенос/копирование клиентских договорных цен между версиями.
- Изменения интерфейса v1 и запрет заказов по выключенному рецепту через v1/API.
- Удаление, переименование или изменение состава уже оформленных заказов.

## Dependencies
