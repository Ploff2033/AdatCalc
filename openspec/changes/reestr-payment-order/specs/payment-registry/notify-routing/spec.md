# Spec Delta

## Purpose

Уведомления реестра адресованы тем, кому нужно действовать: учредителю — о новых заявках и готовых платёжках, бухгалтеру — о том, что можно делать платёжку. У каждого события есть понятный призыв.

## ADDED Requirements

### Requirement: Два адресата
В Настройках → «Реестр оплат» SHALL быть два адресата, «Учредитель» и «Бухгалтер». У каждого ID чата, ID темы (необязательно) и @username (необязательно). Если @username задан, сообщения этому адресату начинаются с упоминания, и Telegram присылает пуш, даже если чат общий. Существующие «ID чата реестра» и «ID темы реестра» становятся адресатом «Учредитель» без перенастройки. Адресат без чата не получает ничего, и работа реестра от этого не меняется.

#### Scenario: Миграция
- **WHEN** до обновления был задан чат реестра -1001 с темой 7
- **THEN** после обновления адресат «Учредитель» — чат -1001, тема 7, адресат «Бухгалтер» пуст

#### Scenario: Упоминание
- **WHEN** у адресата «Бухгалтер» указан @buh_adat
- **THEN** сообщения бухгалтеру начинаются с «@buh_adat»

### Requirement: События и тексты
Система SHALL отправлять события адресатам по таблице. Каждое событие включается и выключается в Настройках:

| Событие | Адресат | Начало текста | По умолчанию |
|---|---|---|---|
| Новая заявка | Учредитель | «Новая заявка №…» | вкл. |
| Одобрено | Бухгалтер | «❗️❗️❗️ Можно делать платёжку» | вкл. |
| Платёжка готова | Учредитель | «✅ Платёжка готова — проведите оплату» | вкл. |
| Платёжка отменена | Бухгалтер | «Платёжка по №… отменена» | вкл. |
| Отклонено / отложено | Бухгалтер | «Решение по №…: отклонено» / «отложено» | выкл. |
| Оплачено | Бухгалтер | «Оплачено №…» | выкл. |

В сообщении: номер, получатель отдельной строкой, сумма (для одобрения — «к оплате»), причина, если есть, и ссылка на заявку с токеном учредителя.

#### Scenario: Одобрение
- **WHEN** учредитель одобряет заявку №291026-5, ООО «ФОРА», 95 450,00
- **THEN** бухгалтеру приходит «❗️❗️❗️ Можно делать платёжку: №291026-5», строка «ООО «ФОРА»», «К оплате: 95 450 ₽», ссылка; учредителю ничего не приходит

#### Scenario: Платёжка готова
- **WHEN** по №291026-5 отмечена «Платёжка готова»
- **THEN** учредителю приходит «✅ Платёжка готова — проведите оплату: №291026-5» с получателем и суммой

#### Scenario: Событие выключено
- **WHEN** событие «Оплачено» выключено, и вносится оплата
- **THEN** сообщение не отправляется

### Requirement: Пакетные события
Пакетное одобрение и пакетная «Платёжка готова» SHALL давать по одному сводному сообщению своему адресату:
- «❗️❗️❗️ Можно делать платёжки: K заявок на S ₽»;
- «✅ Платёжки готовы — проведите оплату: K заявок на S ₽».

В сообщении до 15 строк «№ · получатель · сумма» и «…и ещё N». Пакетное «отложить» — по правилу события «Отклонено / отложено».

#### Scenario: Пачка одобрений
- **WHEN** пачкой одобрены 3 заявки на 520 000,00
- **THEN** бухгалтеру одно сообщение «❗️❗️❗️ Можно делать платёжки: 3 заявки на 520 000 ₽» с тремя строками

### Requirement: Доставка не меняется
Отправка уведомлений SHALL идти тем же механизмом, что сейчас: прокси, очередь повторной отправки, без задержки операции. Сбой отправки не отменяет действие в реестре.

#### Scenario: Telegram недоступен
- **WHEN** Telegram недоступен в момент «Платёжка готова»
- **THEN** статус сохранён, сообщение встаёт в очередь повторной отправки

### Requirement: Реакция «сделано» на сообщения-призывы
Бот SHALL ставить реакцию ✍ на свои сообщения, когда призыв выполнен:
- «❗️❗️❗️ Можно делать платёжку» (одиночное или сводное) — когда по всем его заявкам отмечена «Платёжка готова» (или по ним уже внесена оплата после сообщения);
- «✅ Платёжка готова — проведите оплату» — когда после сообщения внесена оплата.

Если условие перестало выполняться («Отменить платёжку», удаление оплаты), реакция снимается. Сбой Telegram при реакции не мешает действию в реестре; реакция сверяется заново при следующем действии с заявкой. Для сообщений, ушедших через очередь повторной отправки, реакция не ставится.

#### Scenario: Платёжка по одобрению
- **WHEN** бухгалтеру пришло «Можно делать платёжку: №291026-5», и по заявке нажата «Платёжка готова»
- **THEN** на этом сообщении появляется реакция ✍

#### Scenario: Сводное сообщение
- **WHEN** в сообщении «Можно делать платёжки: 3 заявки» платёжка готова по двум из трёх
- **THEN** реакции нет; после третьей — ✍

#### Scenario: Отмена
- **WHEN** «Отменить платёжку» по заявке, на сообщении о которой стоит ✍
- **THEN** реакция снимается

#### Scenario: Оплата по готовой платёжке
- **WHEN** учредителю пришло «Платёжка готова — проведите оплату: №291026-5», и внесена оплата
- **THEN** на этом сообщении появляется ✍
