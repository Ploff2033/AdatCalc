# Дашборд доступных к распределению денег

- Маршрут: feature — новая финансовая модель резервов и доступных выплат.
- Этап: interview.
- Цель: показать сумму, которую можно распределить между соучредителями, сохранив деньги на материалы и обязательные платежи.
- Исследование: OpenSpec CLI подтвердил отсутствие активных changes. Git status недоступен: сломан путь Command Line Tools (xcrun).
- Текущее поведение: frontend-v2/js/screen-dashboard.js суммирует totalProfit заказов выбранного месяца; закупка считается отдельно как max(0, stockThreshold − (stockOnHand − stockReserved)) × price, без доставки. Денежный остаток и календарь обязательств в расчёте дашборда не участвуют.
- Зависимости: openspec/specs/payment-registry/requests/spec.md; реестр независим от ДДС, его оплаты не создают денежных проводок. Требуется исключить повторный учёт закупок и платежей.
- Предлагается: главный показатель доступных выплат с расшифровкой фактических денег, обязательств, закупок и дополнительного резерва; при недостаточных данных не показывать достоверную безопасную сумму.
- Открытые решения: горизонт защиты; целевой запас материалов; полнота учёта наличных и банковских денег, обязательств; денежный лимит или также ограничение накопленной прибылью.
- Согласование: отсутствует; код не изменён.
- Проверки: исследование исходников и действующих требований; тесты не запускались, изменения только в записи задачи.
- Следующий шаг: ответы пользователя, завершение интервью, подготовка proposal/specs/design/tasks и одно согласование готового пакета перед реализацией.
