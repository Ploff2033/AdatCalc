## Решения пользователя (2026-11-09)

- При сохранении заказа без НДС учитывать наличный приход полной стоимости, включая доставку. Пользователь подтвердил: «Да вся сумма».
- Все существующие заказы без НДС оплачены, деньги уже в кассе: «Все заказы которые сейчас есть в системе у которых указано что они без НДС оплачены, деньги в кассе». Сверка охватывает всю историю; уже внесённые приходы учитываются, повторный запуск не должен дублировать деньги.
- Долговые отгрузки бывают, но сейчас их не заносят в систему. Их реализация — отдельный будущий объём.
- Пользователь отдельно потребовал учитывать редактирование заказов, в том числе смену «с НДС / без НДС».
- Отгрузки фактически не ведутся: пользователь назвал их рудиментарными. Не опираться на заполненность даты/факта отгрузки для автоматического прихода.
- Формат дальнейшего интервью: строго один вопрос за раз, по явному требованию пользователя.
- Приход отражается датой заказа, включая внесение задним числом. Пользователь подтвердил: «Да, в сути рабочие заводят день в день. Все должно биться».
- При отмене наличного заказа ожидается возврат денег; на случай редкого исключения при отмене следует показывать подтверждение «Возвращали ли клиенту ДС?» и корректировать кассу в зависимости от ответа. Точный вариант интерфейса/проводки уточнить при сборке пакета, сохраняя подтверждённый смысл.

## Предположения агента, требующие уточнения

Уточнение пользователя от 2026-11-12: «Пока заказ не оплачен его не заводят в систему в случае с налом». Наличный заказ в системе подтверждает уже полученную оплату; ожидание оплаты при создании такого заказа не требуется. Это не отвечает на вопрос о судьбе денег при последующей отмене заказа.

- Ранее предложенная автоматическая компенсация при смене НДС и автоматическое изменение прихода при правке суммы не считаются окончательно согласованными: необходимо выяснить, отражают ли эти действия исправление данных либо реальный возврат/доплату.
- Сторно проведённых записей — правило проекта; когда и какой суммой оно должно применяться к заказу, зависит от ответов на вопросы ниже.

## Будущий модуль «Долг»

Явное требование пользователя: при оформлении заказа должен быть выбор **«Отгрузили в долг»**. Сохранить для реализации модуля «Долг»; сейчас этот выбор не добавлять.

При проектировании долга отделить факт отгрузки и признак НДС от факта получения денег: отгрузка в долг не должна создавать фиктивный приход наличных. Погашение долга, частичные оплаты и переходы между состояниями проработать в будущей задаче; сейчас эти правила не согласованы.
