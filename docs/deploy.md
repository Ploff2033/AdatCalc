# Выкладка приложения и зимних рецептов

Проект работает на сервере через Docker Compose; каталог приложения на сервере — `/opt/adat-calc`. Production `.env` хранится только на сервере и не заменяется файлами из репозитория.

## 1. Подготовка и выкладка кода

Сначала закоммитьте и отправьте нужную версию в `origin/main`. Затем подключитесь к серверу и выполните:

```bash
cd /opt/adat-calc
./scripts/backup.sh
git pull --ff-only origin main
docker compose up -d --build calc
docker compose ps
docker compose logs --tail=100 calc
```

Проверьте, что сервис `calc` запущен и в логах есть сообщение `Сервер запущен`. При старте приложения `backend/schema.sql` автоматически добавляет недостающую колонку `recipes.is_active`; существующие рецепты получают `TRUE`.

## 2. Перенос зимних рецептов

После успешного запуска новой версии выполните в каталоге `/opt/adat-calc`:

```bash
docker exec -i adat-calc-db psql -v ON_ERROR_STOP=1 -U calc calc < scripts/transfer-winter-recipes.sql
```

Транзакция проверяет наличие заводов «Джага» и «Теберда», исходных рецептов с П1 и единиц измерения. Она добавляет на каждом заводе материал «Криопласт Альфа» по 53 ₽/кг, затем создаёт 15 копий для «Джаги» и 16 для «Теберды». В зимних копиях П1 заменён Криопластом по формуле `масса цемента в тоннах × 17 кг/т`; копии сохраняют прайсовую цену и изначально выключены для новых заказов v2.

При несовпадении исходных данных SQL завершится ошибкой и вся транзакция откатится. Повторный запуск не создаст дубли: если зимние названия уже присутствуют, транзакция отклонится целиком.

## 3. Проверка переноса

Ожидаемые количества рецептов по заводам:

```bash
docker exec -i adat-calc-db psql -U calc -d calc -c "SELECT p.name, count(*) AS winter_recipes, count(*) FILTER (WHERE NOT r.is_active) AS inactive, count(*) FILTER (WHERE EXISTS (SELECT 1 FROM recipe_items ri JOIN materials m ON m.id = ri.material_id WHERE ri.recipe_id = r.id AND m.name = 'Криопласт Альфа')) AS with_cryoplast, count(*) FILTER (WHERE EXISTS (SELECT 1 FROM recipe_items ri JOIN materials m ON m.id = ri.material_id WHERE ri.recipe_id = r.id AND m.name = 'Добавка П1')) AS with_p1 FROM recipes r JOIN plants p ON p.id = r.plant_id WHERE p.name IN ('Джага', 'Теберда') AND r.name LIKE '% Зима' GROUP BY p.name ORDER BY p.name;"
```

Ожидается: «Джага» — 15 рецептов, «Теберда» — 16; `inactive` и `with_cryoplast` равны количеству рецептов, `with_p1` равно 0. Затем откройте `/v2/`, выберите каждый завод и проверьте зимние рецепты в справочнике. Они должны быть выключены в списке новых заказов; летние варианты и уже оформленные заказы должны остаться без изменений.

## 4. Ошибки и откат

- Если транзакция завершилась ошибкой, проверьте её текст. Изменения базы откатились; исправьте данные или скрипт и запускайте повторно только после проверки причины.
- Не удаляйте рецепты вручную после успешного переноса: по ним могут появиться клиентские цены или заказы.
- Для восстановления базы из резервной копии используйте `scripts/restore.sh <backup.sql.gz>` только после согласования: восстановление заменяет текущую базу и потеряет изменения, внесённые после резервной копии.
